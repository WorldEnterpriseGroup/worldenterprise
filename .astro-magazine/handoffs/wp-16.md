## What changed

### Layout (visual-brand P0-1, P0-2, P0-4)

| Finding | Fix |
|---|---|
| Wide tables clipped with no scrollbar, and no test could see it (`.page` and `main` had `overflow-x: clip`) | Both `overflow-x: clip` declarations are gone. Every Markdown and MDX table is framed by `<div class="table-wrap" tabindex="0" role="region" aria-label="Table: ...">`. The frame scrolls, has a scroll cue (edge fades, no JavaScript), a visible focus ring and a unique name from its caption, the heading above it or the page title. Header cells take `scope="col"`. The plugin is `src/lib/rehype-table-wrap.ts`, registered as a Sätteri hast plugin (`satteri({ hastPlugins: [tableWrapPlugin] })`) because Astro 7 renders `.md` and `.mdx` with Sätteri and not remark. |
| Forms ran past the column at 320 and 390 | `.field` is one `minmax(0, 1fr)` track, controls are `inline-size: 100%`, the fieldset has `min-inline-size: 0`. |
| `/insights/` desk rows showed two cards and hid the rest | From 48rem `DeskRail` wraps into a grid. On a phone the row still scrolls and keeps its peek of the next card. |
| Header and body started at different x | `PageHeader` takes `measure="prose"` for layouts whose body is the 46rem column; `.container--wide` is deleted. |
| The QA blind spot | `tests/e2e/support/overflow.ts` measures the bounding box of every element against the viewport (a scroll container excuses what is inside it, a clipping ancestor never does). `tests/e2e/layout.spec.ts` runs it on every route at 1440, 390 and a new 320 project, and adds the table, form, desk row and header alignment tests. |

### Navigation and the shell (visual-brand P1, a11y P1-1, P1-3, P2)

- The logo holds its 160px minimum from 1100px and grows to 256px by 1279px. Nav type steps down 1px under 1280px.
- Mega panel links are grids: hex bullet, label and a 38ch description, the label closer to its own description than to the next link, one amber mark (the featured card edge) and cropped hex cells on the featured card (SAGE-PLAN 5.2). The description sits inside the anchor with `aria-hidden` and `aria-describedby`, so the accessible name stays the label.
- The mobile drawer wraps Tab and Shift+Tab, takes focus on open, returns it to Menu on close and sends stray keyboard focus back in.
- `--apply-bar-h` drives the bar height, `scroll-padding-block-end` and the footer padding, so a focused control is never under the bar (WCAG 2.4.11). The bar is not rendered on `/apply/` and `/contact/`.
- `activeSectionId` (the only change to the frozen `src/data/nav.ts`) returns no section on `/apply/`, `/contact/` and `/trust/`. The header Apply button is `aria-current="page"` on `/apply/`.
- `--color-border-strong` darkened to 3.6:1 on white and 3.2:1 on mist (WCAG 1.4.11).
- Islands: `nav.ts` hover and leave timers are per trigger, `aria-haspopup` is removed from the disclosure buttons, `search.ts` cannot fetch the same batch twice and `connectedCallback` is idempotent, `copy.ts` survives a malformed target selector, tabs become `role="tabpanel"` and tab stops once the script runs, the error summary is `role="group"`, and the article topic eyebrow reads "Topic: build" to a screen reader.

### CSP: the style attribute exception is gone (EX-CSP-STYLE-ATTR)

Every inline `style` attribute became a class: `Grid` takes a typed `min` with one `.grid--min-*` class per value (9, 15, 16, 17, 18 and 20rem), `Stack` takes `tight` or `loose`, `Hex` takes `sm`, `md` or `lg`, the altitude steps take `.altitude__step--rise-N`, the styleguide swatches colour an SVG `rect`. `src/lib/csp.ts` no longer lists `{ resource: "'unsafe-inline'", kind: 'attribute' }`, so the page policy has no `unsafe-inline` anywhere and no `style-src-attr`. WP-19 had not touched that exception when I merged. Guards: `tests/unit/wp-16/csp-style-attr.test.ts` (no source writes a style attribute, the class lists agree), the shell e2e (no built page carries one, the policy has no `unsafe-inline`), and `tests/unit/wp-15/csp.test.ts`.

## Remaining

- `e2e:stability` was a knife edge on four phone routes (`/services/customer-and-market-development/`, `/research/dedicated-team-agency-or-freelancers/`, `/insights/cutting-an-mvp-the-cut-line-test/`, `/insights/the-founder-time-budget-of-a-raise/`). The last breadcrumb fit one line in the web font with 1 to 3px to spare and wrapped in the fallback font, and the insight byline did the same, so the page moved 27px at the font swap and scored 0.10 to 0.15. It failed three times in a row in 64250 and passed on a job retry, with identical source in 64227 and 64234. The breadcrumb is now always one line (only the current page, which the h1 repeats, ellipsises, on the span as a block so its box fits) and the byline holds two lines on a phone. `layout-shift.spec.ts` is the guard and `tests/unit/wp-16/layout-css.test.ts` pins the CSS.
- The tab-stop test (`menu.spec.ts`, "no tab stop on a long page is hidden behind the bar") waits for the smooth scroll to stop before it measures, skips the bar's own stop, and for a control taller than the space above the bar (a long table frame) only requires that its start is on screen and above the bar.
