# WP-91 handoff: discoverability at scale

Issue #71, branch `wp/91`. Checkpoint 1 (twins, llms files, sitemap, feed, audit) is described first; checkpoint 2 (search, palette) follows.

## What changed

- **Twins.** `src/components/geo/assemble.ts` picks every page that gets a twin and `mdx-transform.ts` converts the MDX body. The conversion is fail-closed: a component it does not know, an expression it cannot read or a lint failure means no twin and no link to one (the reason is kept in `skipped`). New: `family-twin.ts` builds the twins of the founder segment, industry, comparison and journey pages and of the industries, compare and journey hubs from the same views the templates render (`src/components/families/view.ts`) and the same fixed words (`copy.ts`). A family page gets its twin when the registry launches its slug and a pages entry holds it, so WP-72 to WP-75 need no change here.
- **llms.txt** gains `Insight desks` and `Page families` sections generated from `DESK_DEFINITIONS` and the family registries, filtered by `isLive`. **llms-full.txt** is planned in tiers (`planLlmsFull`): the curated first tier, then desks and families, then the rest, newest first, greedily, under `0.9 x 262,144` bytes. `buildLlmsFullTxt` still throws `LlmsFullTooLargeError` above the cap (W8-26). A fabricated 350-route set and the real content both plan under the budget.
- **Sitemap, feed, robots.** The sitemap page and `rss.xml` read the route ledger and the route state, so a non-live or noindex route (a thank-you page included) appears on none of them. `tests/unit/wp-91/feed-sitemap.test.ts` compares the sitemap with the ledger and validates the feed.
- **audit-geo** (`scripts/audit-geo.mjs`) checks the sitemap against the live indexable routes, the feed items against the pages, the palette links against the pages, and that no thank-you route is in a machine list. It reports no new warning on a real demo preview build.
- **D-23.** `tests/unit/wp-91/d23.test.ts` builds every surface from a fixture gated brief and searches the output: no needle of the full text appears. The geo builders read no file; only the open abstract fields of a brief are ever read.

## Search and palette (checkpoint 2)

- **Search chips.** `src/scripts/search.ts` no longer reads only the first 50 matches. The result data is fetched in chunks of 50 up to a ceiling of 500 (`src/components/islands/we-search/hydrate.ts`; the site is about 300 routes), the chips are rebuilt after each chunk with focus kept, and a type filter stops fetching once it has a page of matches. A search with more matches than the ceiling says so in the status line. The type is still read from the URL prefix (`RESULT_KINDS` in `query.ts`, not in my write set): the new families (`/founders/`, `/industries/`, `/compare/`, `/journey/`) show under the existing chips and no new chip was added.
- **Palette.** `src/components/nav/commands.ts` adds entries from the registries: the audience doors, each family hub and launched entry, each insight desk, and the tool routes of the ledger. Every entry passes the same `isLive` predicate as the navigation, so an entry appears only when its route is built; a thank-you route is never listed (the ledger does not launch it into any list). Articles are not listed: they come from the Pagefind index when the visitor types, so the list does not grow with the library. `data-commands` is serialized into every page by `Header.astro` (not mine); it is about 11 KB with every route live and `palette.test.ts` holds a 16 KB budget. If a future package pushes past it, the fix is to load the list from a JSON file in `Header.astro`.
- **Open item.** Header.astro serializes the list into every page; loading it once as a cached JSON file is the long-term answer once the budget is near.

## Twin coverage (WP-41 carry-over b)

- 97 twins on the real content at the time of writing: insights, research, fundability guides, desks, hub, marketing and legal pages, service lines, playbooks, FAQ, glossary, briefs.
- **No twin, by design:** the pages written in the `.astro` file itself (pricing, who it is for, apply, program, investors, network, about, guides index). A second copy of their prose would drift from the page; llms.txt links the page instead. The library templates already have downloads (`src/pages/library/[slug].md.ts`).
- **No twin, a decision for main:** 6 insights and the SAFE guide hold a `data-generic-definition` or `data-claim-allow` marker (cap table basics, the term sheet, SAFE or note, joining as a founding team member, matching a funding route, paying a first team, `/fundability/safe-explained/`). `scripts/audit-claims.mjs` reads a Markdown file as plain text and honors no marker, so converting the element would be a claims finding and dropping it would make the twin differ from its page. The transform refuses the page with a named reason. Proposal for the audit owner: honor the two markers in a twin when the twin keeps the marked element verbatim; then `CLAIMS_MARKER` in `mdx-transform.ts` can be removed and those twins appear.
- **No twin, a decision for main:** `/insights/choosing-the-right-first-investors-for-a-saas-company/` renders `<IntroductionsDisclaimer>`. `tests/unit/wp-30/release-doc.test.ts` fails the build for any `src` file that carries the add-on wording and is not in the counsel checklist (RELEASE.md section 8), so the transform cannot repeat that wording. The transform refuses the component (`SERVICE_DISCLAIMER_REFUSAL`). Fix, in the release lane: add `src/components/geo/mdx-transform.ts` to the checklist with a quote, then the handler can return the blockquote (the previous commit of that file has it).
- `/fundability/investor-readiness-checklist/` is refused because it uses `<ChecklistGroups>`, a component the transform does not convert (it renders a structured list). Adding a handler is small once the component's props are fixed.

## Open items for other owners

- **`src/lib/seo.ts` `isSitemapUrl`** does not strip the preview base path, so in a preview build (`PUBLIC_PREVIEW=1`, base `/worldenterprise`) the noindex ledger rows (`/apply/thanks/`, `/search/`, `/sitemap/`, `/styleguide/`) pass as indexable. The preview sitemap is therefore longer than the ledger set. audit-geo skips the set comparison and the sitemap thank-you check when `preview` is set; production is unaffected (no base path). Fix: compare the path after removing the base.
- The wp-71 pages `/founders/`, `/industries/`, `/compare/`, `/journey/` hubs exist only when their `index` entry exists; the twins follow the same rule.
