## Release from a tag (R-2, team decision DP-1)

The `mirror` job and its approval gate now belong to `release-*` tags, not to `gh-pages`. The gate refuses a branch pipeline and an unprotected tag. A release tag runs the whole qa set strictly with `verify:release` allowing nothing, so a candidate tag is red until `PUBLIC_WE_INTAKE_API_URL` is set. `release-1-rc1` (3a674bc) is superseded, DO NOT RELEASE: pre-article-fix wording; it stays because tags are immutable. The candidate for counsel is `release-1-rc2` (99e3f37, tag pipeline 64949: green except the expected `verify:release` and the skipped `mirror`). RELEASE.md section 4 has the tag, push and approval steps. The protected tag rule `release-*` (Maintainers) was added through the API on 2026-10-09 and verified with a GET.

## Why the mirror does not push (R-1)

GitHub is already fed by the nightly `weg-ghpages-mirror` CronJob (nebula `tools/weg-ghpages-mirror`, 03:23 UTC, fast-forward only, short-lived GitHub App installation token, this repository on its allowlist). A CI push with a PAT and `--force` would be a second writer. The wp-19 instruction to set `GITHUB_TOKEN` is obsolete. The consequence, recorded in RELEASE.md section 2: the cron publishes whatever is on GitLab `gh-pages` regardless of CI, so the real gates are the `gh-pages` branch protection (only the owner pushes) and the strict GitHub Actions build.
