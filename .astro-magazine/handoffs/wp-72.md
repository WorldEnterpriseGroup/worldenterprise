# WP-72 handoff

Customer journey pages and the rebuilt Resources hub (issue #52). Branch `wp/72`, integration branch `demo`.

## What shipped

- **Four journey pages**, all in the `pages` collection with `family.id: journey` (no route file, W8-29): `/journey/` (stage awareness), `/journey/after-you-apply/` (consideration, step 2), `/journey/first-months/` (consideration), `/journey/onboarding-checklist/` (onboarding). They stay inert until the WP-71 family template (`src/pages/journey/[page].astro`, `[...hub].astro`) is on `demo`; the ledger rows already exist from `src/data/families.ts`.
- **Resources hub** (`/resources/`, a rebuild of an existing route): `src/pages/resources/index.astro`, `src/pages/resources/_ResourceGroup.astro` and `src/components/reference/resources.ts`. Two lists: "Start where you are" (three stages, a short curated path each) and "Everything, by kind" (every live playbook, template, guide, tool, research brief, brief topic, article desk, founder situation, industry and comparison, plus reference pages). Every list is filtered by `getRouteState().isLive`, so a route that is not built is not listed, and a group with nothing live disappears.
- **Tests**: `tests/unit/wp-72/` (30 tests: journey content, resources builders, sentence ledger) and `tests/e2e/wave8/wp-72/` (`journey.spec.ts`, `resources.spec.ts`; both skip a route that is not built).
- **Sentence ledger**: `.astro-magazine/sources/wp-72.json`, five documents (the four journey files and `src/components/reference/resources.ts`, the module that holds the hub's words; an `.astro` file cannot be a document because its code fence is read as YAML frontmatter).

## Decisions

- **W8-25 stands in for DP-W8-16.** `DP-W8-16` is not a heading in `decisions.md`, so the checker cannot resolve it. A journey sentence that no program page states maps to W8-25 (the journey is a contract). If a decision for "no durations" is added later, re-map those rows.
- **`after-you-apply` is step 2.** The page reads the application from WE's side, so it sits at the second of the five steps. `first-months` has no step because it walks all five.
- **No durations.** Neither the pages nor the tests allow a digit before a unit of time, "30/60/90", or a spelled-out span. The page name "Your first months, in order" is the one exempt phrase, and a self-test pins that.
- **Resources titles are not typed twice.** A card's title and description come from the target page's own content entry (`metaLookup`); `STATIC_META` covers the pages that have no entry (library, glossary, FAQ, search, and the three family hubs). A content entry with the same route wins, so a package that adds one changes the hub without editing this file. A live route with no title throws at build time, never a blank card.
- **Family registry entries are listed by label only** (`familyLabel`), so an entry with a `blockedWord` never shows a title or description.
- **Dropped from the old hub**: the "newest brief" and "latest insights" sections. They put dynamic article text on a page whose every sentence must be ledgered.
- **Ledger rule for the hub.** Owned copy (page strings, group titles and intros, the strip) is held strictly: unmapped fails, stale fails. Item titles and descriptions are read from other pages and mapped to the file they come from; a page another package adds does not break WP-72's test, as long as its source file really holds the sentence.
- **Statement of funding**: the hub carries the funding disclaimer (`NoFundingDisclaimer`, C-05) in the "When you prepare to raise" group; the journey hub and the checklist carry C-05 in a sentence.

## WP-71 template (merged to demo, !16)

1. **Order of the MDX body.** The template renders callout, MDX, steps, questions, checklist, sources. WP-71 declined to reorder or add an `after` slot in !16, so the pages are written to work in that order. A steps-first hub would read slightly better; it is an additive WP-71 follow-up the lead can schedule (listed in the wave 8 carry-over).
2. **Forward link on the checklist page.** The last journey page points at `/tools/` through its own "Where to go next" section, and the template's hub action does the same. The two agree.

## Questions the program pages leave open (OP-PROCESS)

The journey pages put these to WE as founder questions and state no answer: what the written scope names as out of scope, how the agreement describes how WE is paid, which subcontractors WE manages, and what a review contains. The program pages are silent on each. If the owner decides any of them, the journey page can state it in a later pass.

## How to regenerate the ledger

The journey rows come from `tests/unit/wp-72/page-copy.ts`; the resources rows come from `tests/unit/wp-72/resources-copy.ts`. If a journey sentence changes, the unit test names the unmapped sentence; add a row (or re-run a generator, which rewrites the whole file, so keep the resources document).
