## Behaviour worth knowing

- One server-rendered `<form method="post">` with every fieldset in the DOM. JS groups them into four steps (About you, About the idea, Team and package, Review). The bar, Back/Next and the package select ship `hidden`; with JS off the form is exactly the old one.
- The package rides in `message` as the last line (`Package interest: <Name>` or `Package interest: not sure yet`). It is never a payload key, so the closed intake schema is unchanged. The select is nameless (`data-field="package"`). `?package=` is read leniently: one valid id, any case, or `not-sure`; anything else is ignored.
- No PII persisted (DP-13): step state is in memory only. No storage, cookies or history.
- Enter in a text or email input on a non-final step means Next. Implicit submission does nothing while the submit button is disabled (disabled mode, the default build), so `attachEnterAsNext` in `forms.ts` handles keydown.
- WCAG 2.4.11: the bar is sticky on mobile and the scroll-margin reads `--stepper-bar-h`, which a ResizeObserver sets to the measured height (the status line can wrap at narrow widths). Focus moves to the step heading (`tabindex=-1`); the status line is `role=status`, `aria-live=polite`.
- Submit stays disabled in markup because the intake endpoint is unprovisioned.
- `apply.mdx`: three sentences are unchanged from wp/40 ("Tell WE about the idea.", "WE is fully remote...", "You apply from where you are."). `tests/unit/wp-43/sentences.ts` lists them as `APPLY_MDX_UNCHANGED`; all other sentences on the page are mapped.
