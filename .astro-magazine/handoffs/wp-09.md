# WP-09 handoff: SEO, schema, distribution, sitemap page, 404

Branch `wp/09`. Verified in CI only (verify:static, e2e:smoke, check:ownership). Both audit scripts were also run read-only against the `dist` artifact of the branch pipeline.

## Routes delivered

- `/sitemap/` (HTML site map, noindex,follow): launched, indexable ledger routes that exist, grouped by section; labels from nav data then collection titles.
- `/404.html` (ReferenceLayout, noindex): root-relative base-aware links; search form (GET `/search/?q=`) and section links render only when those routes are live.
- Machine routes: `/robots.txt` (production allow-all plus `Sitemap:`; preview `Disallow: /`), `/rss.xml` (published insights and research whose route is live, newest first; valid with zero items, which is the current state), `/.well-known/security.txt` (no file until `site.securityContact` is set; verified that an empty endpoint response writes no file in Astro 7.3.6's build).

## Files

- `src/lib/seo.ts`: titles, canonical, robots, plus `isSitemapUrl`, `withLastmod`, `robotsTxt`, `securityTxt`, `speculationRules`, `groupSitemapRoutes`.
- `src/lib/schema.ts`: sitewide and page builders, `serviceNode`, `faqPageNode`, `definedTermSetNode`, `articleNode` (type `Report` for briefs), `ALLOWED_TYPES`/`FORBIDDEN_TYPES`, `withSearchAction`, `pruneDanglingBreadcrumbs` (called inside `graph()`).
- `src/components/seo/{SeoHead,JsonLd,SpeculationRules}.astro`: SeoHead adds RSS alternate and sitemap links; JsonLd adds the WebSite `SearchAction` only when `/search/` is live; SpeculationRules registers its sha256 with `Astro.csp?.insertScriptHash` (no-op until CSP is enabled).
- `scripts/audit-seo.mjs`, `scripts/validate-jsonld.mjs` (Node built-ins; importable, CLI guarded). `tests/unit/wp-09/**` (30 tests, run in `test:unit`).
- Sources: `.astro-magazine/sources/wp-09.json` (RFC 9116, installed Astro types). No statistics or business claims were added.

## How to use (page WPs)

- Per-page JSON-LD goes through the `jsonLd` prop of the layouts: `serviceNode({ path, name, description, serviceType })` for service lines, `articleNode({... type: 'Report' })` for briefs, `faqPageNode(path, items)` on `/faq/`, `definedTermSetNode(path, name, terms)` on `/glossary/`. Use `schemaType` for `CollectionPage`, `AboutPage`, `ContactPage`.
- Only types in `ALLOWED_TYPES` pass `validate-jsonld`. Offer, Review, Person, Event and ratings fail the build audit.
- Titles are `{Page} | World Enterprise Incubator` (60 max); `audit-seo` fails longer titles, descriptions over 160, duplicates among indexable pages, non-self canonicals, a missing or second `h1`, and skipped heading levels inside `<main>`.

## Findings

- Real built output has about 15 `<h2>` mega-panel headings before the `<h1>`; the audit judges `<main>` only (request W13-2).
- Before this WP the home page and 404 emitted a `breadcrumb` `@id` that resolved to nothing; `validate-jsonld` caught it on the old artifact and `graph()` now removes it. On the branch artifact both audits pass except the sitemap rule below.
- `/sitemap/` currently appears in `sitemap-0.xml` because the sitemap config is frozen. `audit-seo` reports it; wire with `--sitemap=warn` until W15-1 lands.
- `og:image` is absent everywhere (FLAG-OG, placeholders); reported as a warning count, not an error.
- CSP: evaluated against the installed astro 7.3.6 types. Supported and recommended, but not enabled (frozen config); config, directives, risks and accepted exceptions are in the requests file (W15-2).
- Speculation Rules: `eagerness: 'moderate'` and `href_matches` are as specified; the rules are base-aware and exclude `/apply/thanks/` and `/search/`.
- Not done by design: `lastmod` (config is frozen; helper and reference algorithm provided), an Offer or Event node, a `foundingDate`.
