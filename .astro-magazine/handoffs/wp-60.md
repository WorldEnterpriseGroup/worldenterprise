## Findings

- **Sätteri.** The hast tree supports `insertAfter`, and `ctx.fileURL` is available to a hast plugin, so the mid-body CTA marker fallback was not needed. `midCtaPlugin` reads the route from `ctx.fileURL` and inserts static HTML after the first paragraph that ends at or after 50 percent of the body and no later than 90 percent; a body under 900 words gets no mid band.
- **Q-7 (does the audit read an `href`).** It does not. A link address in an `href` or in plain text is clean, and so is a `<link rel="canonical">`. The audit does read a URL in JSON-LD, in an `og:url` meta, in a sitemap `<loc>` and in a feed, and `\baccelerators?\b` matches inside the slug there. The slug was therefore renamed before any page exists: `/compare/incubator-vs-other-programs/` (registry label "Incubators and other startup programs", with `blockedWord`). `C-13-peers` gains one `allowPaths` pattern for that page (its Markdown twin maps to the same route), the list is four patterns, and `W8-C13-own-peers` has none. `families.test.ts` proves the slug and label are clean and that no other path gains an exception. **For the counsel queue:** the comparison page is the one place the word is the subject; WP-99 commits the CR entry.
- **Retry-After and CORS.** A browser hides every response header except the safelisted ones from a cross-origin page. The intake endpoint is cross-origin, so without `Access-Control-Expose-Headers: Retry-After` the form cannot read the wait and says "a few minutes". The contract (section 5, item 1) now requires it and `tests/e2e/forms.spec.ts` mocks it.
- **MR pipelines.** `merge_request_event` pipelines fail instantly with no jobs on this project (MR !14 shows it too). Only branch (`push`) pipelines run; the push slot reads those.
- **Article rubric waivers.** 18 originals are pinned by sha256 in `tests/unit/wp-60/fixtures/existing-articles.json` and waived for three rules only: `cannot-tell-you`, `internal-links` and `words`. Five of them count 1,050 to 1,200 words by `countWords`. A new article gets no waiver.

## CTA decisions

- Policy (contracts section 6): honest copy, one primary and at most one secondary per page, no urgency, no count, no popup, no sticky bar.
- Resolution order: a page's frontmatter `cta`, then the surface default, then the layout default, then none. A target whose route is not live is dropped (fail closed), so the secondary link disappears rather than going dead.
- The mid band is static hast, only in a body of at least 900 words. The end band is the layout's `cta-end` slot. The aside variant is `CtaAside`. `AudienceStrip` is the four doors for the home page and the hubs.
- The live-route lookup is `src/data/cta/live.ts`; it sits in `src/data/cta/**` (WP-60's write set), not in `src/lib`.
- WP-62 refines the words in `src/data/cta/targets.ts`; the ledger test fails on a sentence it did not map.
