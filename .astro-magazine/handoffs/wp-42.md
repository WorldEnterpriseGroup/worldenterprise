## How it works

- `/pricing/` opens with four package cards (`PackageCards`), then the seat explainer, the stage picker, what drives the number of seats, the Investor Introductions offer, the not-published block and the FAQ. Every package name, stage sentence and depth is rendered from `src/data/packages.ts`. `pricing.mdx` imports that module and no longer holds the table.
- Each card links to `/apply/?package=<id>` and to `/tools/team-composer/?package=<id>`.
- The picker works without JavaScript as a list of stages, each linking to its card (the `:target` card shows the "Sized for your stage" flag). With JavaScript it becomes radio buttons, announces the result in a polite live region that is empty at load, and marks the card with `data-suggested`.
- The Composer carries the package three ways. A real `<select name="package">` sits in the one GET form, so the plain form reaches `/apply/?package=<id>` with no script. On load the script reads `?package=` (exactly one known id; empty, unknown or repeated values are ignored), names the package above the sketch, keeps the address in step with the select, and updates the Apply links in the call-to-action band. The enhanced handoff is `/apply/?package=<id>#team=<roles>`, the query before the fragment.
- `applyHandoffHref(path, selection, pkg = null)` keeps its two-argument behavior. The package is deliberately not added to the copied team text, so nothing implies a seat count for a package.

## Deviations from the plan, and why

- The roles table and its rate-column logic (`flags.seatPrice.published`) moved from `src/pages/pricing/index.astro` into `SeatExplainer.astro`, so `index.astro` no longer imports `DataTable`, `ROLES` or the flags.
- The hero primary action on `/pricing/` is now a jump to `#packages`, the page's first block. The secondary action is the rate request.
- The picker sits after the seat explainer, as the plan orders it. Cards, explainer and picker own their headings, so `pricing.mdx` has fewer headings of its own.
- The Composer select uses short stage labels ("First product (Launch)"). The verbatim stage sentence appears in the banner once a package is chosen and beside each radio on the pricing page. The labels are derived (`stages.ts`) and unit-tested to use only words from their sentence.
- `NotPublished` says "the add-on" and never names Investor Introductions, so the disclaimer-wherever-named rule is not triggered by it. The offer block and the FAQ answer are unchanged.
- `pricing.mdx` keeps the sentence "This page lists no amounts. WE shares the current rate ..." verbatim, because the counsel checklist quotes it.
