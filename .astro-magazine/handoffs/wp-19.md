### CSS decision (P1-1)

`build.inlineStylesheets: 'auto'` plus `vite.build.assetsInlineLimit` as a function: stylesheets use Vite's 4096 B default, every other asset type stays a file (`false`). Result: one render-blocking stylesheet request instead of 3.13.

Option 2 (inline everything) removes the last request but makes the HTML carry 36 KB of raw CSS per page. It was not faster on mobile Lighthouse (FCP 1484, LCP 1832) and it moved the font swap enough to fail `e2e:stability` (3 failed, 3 flaky). Rejected, branch history kept in pipeline 64237.

## What changed, by brief item

### Performance and SEO

- P1-1 CSS inlining: `astro.config.mjs`. Proven above.
- P1-2 fonts: 13 `src/assets/fonts/*.woff2` replace the `.woff` files (fontTools re-wrap, table for table; glyph outlines, metrics, names and coverage compared with fontkitten). `astro.config.mjs` font `src:` entries and `scripts/build-og.mjs` read the new files. `tests/unit/wp-19/fonts.test.ts` checks the `wOF2` signature, not the file name. `src/assets/SOURCES.md` documents the conversion. Reserved Font Name: format conversion only, no subsetting and no rename; licences still ship beside the files.
- P2 wordmark: `src/assets/brand/we-logo-wordmark.svg` and `public/press/we-logo-wordmark.svg` (byte-identical, 8,119 B; sixteen two-identical-stop gradients became flat fills, SVGO precision 2, raster diff at 1x, 2x, 4x shows no pixel off by more than 18 of 255, only on antialiased edges). `wordmark.test.ts` keeps the two copies identical.
- P2 JSON-LD: Organization logo is the stable `/press/we-logo-wordmark.svg` URL (`LOGO_PATH`, `logoUrl()` in `src/lib/schema.ts`), never a hashed build asset. Article and Report nodes get the social card as `image` (`withArticleImage`); a node that already has an image keeps it. `scripts/validate-jsonld.mjs` checks both.
- P2 social cards: `/insights` and `/research` map to `og-resources` in `src/components/media/OgMap.ts` (no new image generated; AVIF `og:image` unchanged).
- P2 sitemap: `lastmod` is the date the page itself declares (`dateModified`, then `updatedDate` and so on; `publishedDate` added to `DATE_KEYS`; page-file literal before git). `scripts/audit-seo.mjs` compares each sitemap `lastmod` with that page's `article:modified_time` and fails on a difference.
- security.txt: `securityContactUri` in `src/lib/seo.ts` accepts https, mailto and tel as written. The file stays absent until `site.securityContact` is set (it is `null` in frozen `src/data/site.ts`). `Policy:` and `Acknowledgments:` were not added: `site.ts` is frozen and they would be new claims.
- Removed a speculation rule that never matched (dead `selector_matches`).

### Security P1

- No-JS forms: every form is `method="post"` and `planForm` (`src/data/forms.ts`) decides the no-JS behavior. Apply and Contact in endpoint mode post form-encoded to the endpoint with a hidden `form` field and, for Apply, a `redirect`. Newsletter, a mailto form and a disabled form ship the submit button `disabled` in the markup and `src/scripts/forms.ts` enables it on mount (`data-mounted="true"`). `<noscript>` notes say why. Contract text: `docs/forms-contract.md` section 8.
- No-JS e2e (`tests/e2e/forms.spec.ts`, `without JavaScript`): Apply and Contact post form-encoded to the endpoint with no query string; Newsletter cannot post, its button is disabled, and the note shows; one `with JavaScript` test proves the button enables on mount. Pipeline 64252 failed these for two test-side reasons (found in the trace, not product defects): Playwright's text engine never looks inside `<noscript>` (so `getByText` cannot see the note; the test now uses `noscript .callout__title`), and with scripting off plus `html { scroll-behavior: smooth }` click scrolling never settled the consent checkbox (the block now asks for reduced motion and fills and sends from the keyboard). Green from pipeline 64262.
- `.github/workflows/pages.yml`: `permissions: {}` at the top, per job `contents: read` for build and `pages: write`, `id-token: write` for deploy; every job guarded to `refs/heads/gh-pages`, so the unguarded `workflow_dispatch` no longer does anything from other branches; the build runs `npm run verify:release` with `RELEASE_ALLOW: ''`, copies `CNAME` into `dist`, audits the final dist (`audit-dist.mjs --cname-in-dist`, `audit-csp.mjs`), and only then uploads. Artifact promotion from GitLab is not possible without a cross-platform token, so the workflow rebuilds and verifies instead.
- Mirror: `mirror:` in `.gitlab-ci.yml` extends `.mirror:github` but replaces its `script:`. `scripts/ci/require-mirror-secrets.sh` fails the job, naming the missing variable (never the value), when `GITHUB_REPO` or `GITHUB_TOKEN` is unset, when the repo is not `owner/name`, or when the token has whitespace. The template's remote and push lines are copied unchanged. `release-security.test.ts` checks the order (guard, remote, push) and that there is no `exit 0` path.
- Forms and CSP read one source: `resolveEndpoints` in `src/lib/endpoints.ts` is called once from `astro.config.mjs`; https only; a set but invalid value throws and fails the build; unset stays null. `src/lib/csp.ts` builds `connect-src` and `form-action` from the same result.
- Published-output audits: `scripts/lib/audit-dist.mjs` walks dist recursively against an allowlist (only `.woff2` fonts, no hidden entries, no `.map`), scans for secrets and repository paths, and checks `CNAME` in dist when asked. `scripts/audit-csp.mjs` proves every inline script and style block is covered by a hash and every form origin is in `connect-src` and `form-action`. `audit:dist` (the CI job) runs both, `e2e:forms` runs `audit:csp` on its own build (the only build with endpoints), and `pages.yml` runs both on the final dist. Fixtures in tests are obviously fake (`AKIAEXAMPLEEXAMPLE12`, a runtime-assembled key header).
