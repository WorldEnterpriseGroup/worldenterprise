## How it works

- Every tool is a custom-element island in the pattern of `we-calc`: the server renders all of it with the controls disabled, the script enables them, the logic is a pure module `node --test` imports. The shared kit holds what the three tools have in common: strict entry parsing (`parseEntry`: commas and one decimal point, no exponent, no currency sign, no negative, nothing from one trillion up, a described error otherwise), result blocks of a fixed shape, one two-line note slot per field, a 400 ms settle before a result is rewritten, and one polite `role="status"` region.
- Nothing is stored or sent, and nothing is put in the address bar. The hub, the tools and the shared kit contain no `fetch`, storage, cookie, `history` or `location` write; `copy-guard.test.ts` scans for each, and the e2e refuses every request after load.
- Inputs start empty. No field has a placeholder or a preset value. A result is a number or a stated reason (Waiting, Needs a fix, Not defined), never NaN or Infinity; a sweep of 1,728 input combinations asserts it.
- Every result block carries "An illustration from your inputs, not advice."
- Runway is rounded down to one decimal place, as the runway article says. Growing burn counts whole months while the next fits in the cash left, then a fraction of the month that does not; the count stops at 1,200 months and says so.
- The hub names no count, so a tool that merges later changes no sentence. `registry.ts` holds one entry per tool and the hub lists an entry only when its route is live in the ledger.
- JSON-LD is a `WebApplication` node from `webApplicationNode` (WP-49): `@id`, `name`, `url`, no `offers`, no `price`.
- There is no SAFE calculator (DP-9), no WE price, no amount, no outcome, no "free" and no "success fee". `copy-guard.test.ts` runs every sentence and every result the calculator can write through `claims-denylist.json` and a wider list of wording the tools never use.
