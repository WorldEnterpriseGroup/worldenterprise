# WP-26 handoff: sourced figures on every insight article

Issue #92, milestone "Wave 11: media primitives and media density" (1811). Branch `wp/26-figures`, target `demo`.

## What shipped

- **Registry** (`src/data/insight-figures/`): `sources.ts` (11 public sources WP-26 fetched), `bds.generated.ts` (Census BDS 2023
  tables), `datasets.ts` (BTOS, NIST, OWASP, BLS values), `figures.ts` (28 figures as pure data), `registry.ts` (article to figures).
- **Components** (`src/components/insights/`): `InsightFigures.astro` (the "In the data" section), `InsightBars.astro`,
  `InsightLineChart.astro`, `InsightRankList.astro`. All three sit in the WP-35 chart shell (`ChartFigure`), so each figure has a
  figcaption (title and takeaway), a named SVG (`role="img"`, title and desc), a data table in `DataTable` (`class="table-wrap"`,
  focusable, named by the figure title), a visible source line with link and period, and "Retrieved YYYY-MM-DD". Reused /data/ charts
  (waffle, slope, ridgeline, range, stacked area) take WP-35's props unchanged.
- **Layout**: `ArticleLayout.astro` draws `<InsightFigures path={meta.path} />` after the article body and before the sources list.
  Unregistered paths (style guide, the 12 inline-figure articles) render nothing. No figure markup on the /insights/ index or cards.
- Static SVG and HTML only: no script, no style attribute, no third-party request. Honesty line under the heading: "These figures
  describe U.S. businesses in general, not WE’s results."

## Sources

`.astro-magazine/sources/wp-26.json`: 11 fetches (all 2026-10-16, status 200, allowlisted hosts; census.gov, nist.gov, owasp.org,
bls.gov) and a `figures` array with, per figure, its fetch ids, source lines, derivation note, the exact values it prints and the
articles that show it. The array is generated from the registry (`tests/unit/wp-26/ledger.ts`) and the unit test fails if they differ.
Figures reused from /data/ cite WP-35's fetches (wp-35.json); no fetch is duplicated. No `documents` entries were added, so no article
moves between ledgers. bls.gov refuses curl, so the two BLS pages were read with WebFetch (time nominal, date exact).

## Tests

- `tests/unit/wp-26/figures.test.ts` (18 tests): every article file covered exactly once; every figure resolves; every figure cites
  recorded fetches on allowlisted hosts and its source links are those fetches; ledger values equal registry values; all copy passes
  `cleanText` and the denylist; BDS age classes sum to the published totals; tables are well formed; numbers in descriptions appear in
  their tables; components draw no table outside `DataTable`/`table-wrap`, no script, no style attribute; layout order.
- `tests/e2e/wave8/wp-26/figures.spec.ts`: one article per figure (28) checks caption, framed named focusable table, source link,
  retrieval date, opened-table no-scroll; per route axe (WCAG 2.2 AA, scoped to the section), named drawings, unique table names,
  section before sources, no third party; no-script pass; no horizontal scroll at 1920, 1440, 390 and 320 with every table open.
  The spec lives under `tests/e2e/wave8/` because the Playwright config only runs named common specs at the top level, so a
  `tests/e2e/wp-26*.spec.ts` file would never run in CI; it runs in job e2e:wave8.

## Open items

- Figure choice per article is editorial; the registry is one file, so a desk editor can swap ids without touching components.
- The BDS firm-size file sums to 5,604,596 firms, not the 5,593,727 of the firm-age file (firm size uses a different averaging); the
  size figure divides by its own total and says so in its derivation note.
- Utilities (NAICS 22) is a small sector, so its exit rates move more from class to class; the sector note says so.
