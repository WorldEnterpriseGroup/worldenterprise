## How the templates work (for WP-72 to WP-75)

- A route exists when the registry (`src/data/families.ts`) names the slug, `launch` is true and a `pages` entry `<folder>/<slug>` exists. `getStaticPaths` is `resolveEntries(<REGISTRY>, await getRenderable('pages'))`, so a slug with no file makes no route and a file the registry does not list makes none.
- The page's `family` frontmatter object must carry the right `id` and a `slug` equal to the file name. `assertFamilyData` throws with the entry id otherwise, so a mis-filed page fails the build with its file named.
- Each page renders: hero (actions from contracts 6.2, each candidate checked against the live routes, dead targets dropped), the family's vector composition, the fixed sentence in a callout, the MDX body, then the structured sections from `family` (segments: who it is for, challenges, reading path; industries: buyer, perimeter with jurisdiction, as-of date and numbered source, data questions, sales cycle; comparisons: one table with the same rows for both sides, questions per side, where each fits, definitions; journey: the program steps with the page's step marked, questions, checklist) and a numbered Sources list. The order of the two comparison sides is whatever the data gives; nothing in the template looks at which is first.
- Fixed sentences (`FIXED` in `src/components/families/copy.ts`, mapped to contract rules in `template_sentences` of the sources file) cannot be omitted or reworded by a page.
- An entry with `blockedWord` (`incubator-vs-accelerator`) is described by its label alone in every card.
- Hubs (`/industries/`, `/compare/`, `/journey/`) render their structure with no content entry: generic intro from `HUB_FALLBACK` and an empty card list until pages exist (the card list renders nothing when empty). A content package may add `<folder>/index.mdx` to set the hub's title, description and intro. `/founders/` is WP-62's and `/briefs/` WP-63's.
- Journey step titles come from `PROGRAM_STEPS`; the template adds no step and no duration. A checklist link renders only when its route is live.
- The shared `Card` is not used; family cards are their own component.

## Brand system rules

- D-8: no logo on a dark band. `Lockup.astro` throws at build time on a dark ground (`assertLockupGround`), and the static audit fails any other file that imports the wordmark or the lockup. The site header owns the one lockup every page carries; a family page never adds a second.
- Every brand component takes its colors, spacing and type from tokens; no new stylesheet and no edit to a shared one. `npm run audit:tokens` reports 0.
- Compositions: inline SVG built in `compositions.ts`; no people, logos, product depiction or numbers. Each is `aria-hidden` unless the caller passes a `label`. The content scan is in `tests/unit/wp-71/support/scan-composition.ts`.

## Brand story and brand kit

- `/about/brand-story/` is built from the ORBITAL description, the manifesto, the editorial policy and decisions only. Every sentence is mapped in the sources file (every string of the brand story, the press page and the brand kit is mapped, categorized as quote, claim, UI label, page frame (cap 14) or paraphrase (cap 10)); `story-gate.test.ts` enforces the caps and the claims denylist.
- `/press/brand-kit/` is built behind its `launch: false` ledger row (OP-BRAND, `src/data/routes.ts`). `src/pages/press/[kit].astro` emits no route while the row is false; the page is then absent from the sitemap, the nav and `llms.txt`, and `/press/` shows no link to it. To release: move the row from `L2_RESERVED` into `RAW_ROWS`, flip `launch`, and update the pinned row count in `tests/unit/foundation/ledger.test.ts` (WP-99, after OP-BRAND sign-off). The palette and type tables are read from `tokens.css` at build time, so the kit cannot drift from the tokens.
- The kit is the only page that shows the lockup on its own; the clear space and the no-reversed-logo rule are rendered from `lockup.ts`.
