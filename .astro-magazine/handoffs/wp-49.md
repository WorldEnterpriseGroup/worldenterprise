## How it works

- Both tools are custom-element islands in the pattern of `we-team-composer`: the markup is complete from the server, the script enhances it, the logic is a pure TypeScript module that `node --test` imports. The calculator's inputs and buttons, and the evidence room's stage radios and buttons, are rendered `disabled` and enabled by the script, so a visitor without JavaScript is not handed controls that do nothing and nothing appears or moves when the script runs.
- No layout shift on update: every field has one two-line note slot that holds its hint or its error; every result is a fixed block (name, one line for the value, `minmax(4lh, auto)` for the working, source tag); the evidence room reserves its progress and message lines. Typing settles for 400 ms before the results are rewritten, so a screen reader hears a result once. The e2e compares the position and height of every field and result before and after a fill, an error and an extreme entry.
- Calculator input is parsed strictly (`parseEntry`): thousands commas, a leading decimal point and spaces are accepted; exponents, currency signs, `Infinity`, `NaN`, negatives and values from one trillion up are refused with a sentence that names the field. A result that cannot be worked out says why ("Not defined", with the reason) and one that is waiting says what to enter. No path produces NaN or Infinity (a 600-round hostile-input fuzz asserts it).
- Evidence-room state is `#stage=<key>&done=1a.1b.r3` in the address only (`history.replaceState`, no entry per tick). A hash that is not this page's, such as the skip link's `#main`, is ignored so it cannot clear the ticks. No storage, cookie or request (a unit test scans the script; the e2e records requests and reads storage).
- The copy button writes Markdown task lists for the items the stage shows; if the clipboard refuses, a `<details>` with a read-only textarea opens and the message says why.
- The evidence-room items are phrases of the data-room guide (33 items), the artifacts of the twelve readiness statements (imported, not retyped) and the guide's five pre-share checks. A unit test checks every phrase against the guide text.
- Stage tags are WE's own suggested order and are labelled as such on the page ("a suggestion, not an investor requirement"). The fourth stage has no filter: that company shows all items and asks its own counsel.
- There is no SAFE calculator (DP-9) and the pages never name the Investor Introductions add-on.

## Requests and open items for other packages

- **WP-47 / WP-50: the research brief does not define six of the calculator's results.** `src/content/research/early-stage-saas-metrics-definitions.md` defines only MRR, ARR, customer churn, NRR, simple and extended CAC and CLV. Net new MRR, gross revenue churn (the brief defines customer churn only), quick ratio, CAC payback, LTV to CAC and runway are shown on the page as "commonly calculated this way: a convention, not a WE method", each with a link to a public page that states the formula (Baremetrics, ChartMogul, Wall Street Prep x3, Corporate Finance Institute; recorded as `wp49-ref-*` in `.astro-magazine/sources/wp-49.json`). The standard forms were checked against those pages, and where a page differs from the calculator the difference is stated in the metric's assumptions (net new MRR and revenue churn: the reference folds downgrades into churn or adds them; CAC payback: the reference is the whole-month form). The brief publishes no benchmark; two references do (quick ratio 4.0, LTV/CAC 3.0x) and the calculator repeats neither. Adding these six to the brief's formula table, with those references, would let the page say "formula from the brief" for all nine and would remove the dependency on vendor pages. `formulas.test.ts` already fails if one of the six starts appearing in the brief, which is the cue to relabel it. The reference pages are vendor and training-provider explainers, not standards; if any link rots, the metric's source entry is where to find the replacement.
- **WP-41 dependency.** `WebApplication` is not in `ALLOWED_TYPES` (`src/lib/schema.ts`, `scripts/validate-jsonld.mjs`) on `demo` until `wp/41` merges, so `audit:jsonld` would refuse a page that carries it. The node follows WP-41's contract and the two pages pass it through the layout's `jsonLd` prop. See the pipeline table for whether that wiring is on this branch.
- **WP-50: links to the tools.** The tools are linked from the hub and from each other. `src/data/nav.ts` already points "Founder tools" at `/tools/`. The Team Composer page's breadcrumb still reads Home / Resources / Team Composer (WP-42's file, not touched); a Tools crumb would match the new pages.
